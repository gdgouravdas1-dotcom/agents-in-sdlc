フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストは、ひとつのブランチに保存されています。これらをまとめてレビューし、プルリクエストを作成しましょう。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にプロセスの管理を任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。ワークショップを円滑に進めるため、フィルター機能と品質に関するワークフロー全体をひとつのセッションとブランチで進め、そのすべての作業をこの PR にまとめました。

このレッスンでは、次のことを行います。

- Agent Merge の概要と、マージのライフサイクルを自動化する仕組みを学びます。
- 機能の PR 全体と検証の証拠を確認します。
- レビュー後にのみ Agent Merge を許可し、PR のマージを確認します。

## シナリオ

フィルター機能のワークフロー全体を通じて、Copilot を使用して機能の計画、実装、検証を行いました。Tailspin Toys は、マージの許可を開発者の管理下に置きながら、残りの PR 作業を自動化したいと考えています。

## Agent Merge の概要

**Agent Merge** は、GitHub Copilot app でプルリクエストを取り込むために必要な残りの作業を自動化します。有効にすると、アプリのセッションが PR を読み取り、失敗した継続的インテグレーション (CI) チェックの修正、レビュー コメントへの対応、必要に応じたリベースなど、マージを妨げる問題に対処します。GitHub で許可され次第マージします。バックグラウンドで動作し、アプリを再起動しても継続し、PR がマージされると自動的に無効になります。

ここまでは、自分で **Merge pull request** を選択していました。Agent Merge に任せることもできますが、コードの編集やマージには引き続き明示的な許可が必要です。マージを許可する前に、許可される操作と作業内容をレビューしてください。

## Agent Merge で PR を管理する

コードの作成とレビューが完了したので、Agent Merge に PR プロセスを管理させましょう。

1. エージェント ピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウン項目を選んだだけでは開始しません。

Agent Merge は次の処理を行います。

- タイトルと説明を含むプルリクエストを作成します。
- Issue からセッションを開始した場合は、説明本文で関連する Issue を参照します。
- リベースを行うか、ターゲット ブランチとのマージ競合に対処します。
- CI プロセスを監視し、すべてのチェックが成功することを確認します。
- 他の開発者や Copilot code review からのフィードバックを監視し、コメントを解決する変更を加えます。
- すべてが成功した後、必要に応じて PR を自動的にマージします。

Agent Merge がすべてのチェック成功後に PR もマージするようにします。

5. PR の差分と検証の証拠をレビューしてから、マージを許可します。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. 次のプロンプトで、エージェントにマージを依頼します。

   ```plaintext
   Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
   ```

9. 進捗を確認し、報告された阻害要因があれば解消します。続行前に PR の状態が **Merged** であることを確認します。マージ許可が有効になったことや、エージェントが実行中であることは、マージ完了の証拠ではありません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行前にそれらの阻害要因を解消してください。
