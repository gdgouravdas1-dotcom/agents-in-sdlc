GitHub Copilot をエージェント モードで使うと、コードベースを調査し、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツール呼び出しやファイル編集をリアルタイムに確認できます。差分をインラインでレビューし、変更を個別に採用または取り消し、エディターを離れずに追加のプロンプトで会話を誘導できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッション中に指示を送り、高コントラストに加えてライト モード切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、高コントラスト モードを実装中です。作業の途中で、デザイン チームから追加の要望がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モード切り替えも追加したいとのことです。新しい会話を始めずに、既存のセッションを誘導して機能を追加します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調査するファイル、実行するコマンド、提案する編集など、各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールして、各ツール呼び出しを確認します。ファイルの読み取り、編集、実行を求められるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を取り消してエージェントに再試行させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、セッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツール呼び出し (たとえば、ターミナル コマンドの実行) の許可を求められると、エージェントは一時停止して **Allow** プロンプトを表示します。許可する前に、コマンドを確認してください。

5. エージェントが高コントラスト モードの実装を完了するまで待ちます。変更の概要を示す最終メッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

高コントラスト モードができたので、同じ会話を続けてライト モード切り替えを追加します。同じチャット セッションでは、エージェントは以前の作業、変更したコンポーネント、スタイルの方法、local storage のパターンを把握しています。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調査し、ライト モードの変更を提案します。
3. 高コントラスト モードと同様に、追加された編集をレビューし、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの進め方が意図と異なる場合 (たとえば、切り替え UI を望まない方法でリファクタリングする場合)、チャット入力欄の横にある **Stop** ボタンで停止し、意図を明確にする追加メッセージを送ります。

> [!TIP]
> セッションを途中で誘導すると、最初からやり直すよりも効率的です。追加プロンプトで調整を依頼します (「CSS を簡潔にして、セレクターを重複させず CSS 変数を使ってください」)、軌道を修正します (「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合してください」)、または範囲を広げます (「両方の切り替えにキーボード ショートカットも追加してください」)。

## 作業内容をレビューする

コミット前に、エージェントが変更したファイルをひととおり確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイル一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更ファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターン (ARIA 属性、キーボード ナビゲーション、セマンティック HTML、local storage による保持) が反映されていることを確認します。
4. 問題がなければ Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って実行中のセッションを監視し、各ファイル編集をレビューし、変更を採用または取り消し、コンテキストを失わずに追加プロンプトで作業範囲を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を採用または取り消す
- 追加プロンプトでセッションを途中から誘導する

次のレッスンでは[アクセシビリティの変更をプルリクエストとして公開][next-lesson]し、このラボでローカルのカスタム エージェントが行った作業を確認します。
